# Harness Experiment A/B — one coding agent vs skeleton→body pair

Дата: 2026-10-01. Задача (одинаковая для обоих методов): React-чат-фронтенд к бэку ai-turbo
(задачи T-11…T-19 спецификации `docs/features/react-chat-web/spec.md`; каркас-ветка
`harness-experiment`, ветка `main` = метод A).

## Методы

| | Метод A (базовый харнесс) | Метод B (модифицированный харнесс) |
|---|---|---|
| Кто пишет код | один агент `developer` | два агента: `developer-skeleton` (каркас: сигнатуры + логические комментарии, тел нет) → `developer-body` (тела строго по каркасу) |
| Модель | основная модель сессии | каркас — сильный тир (**opus**), тела — дешёвый тир (**haiku**) |
| Ревью | `05-review.md` | `07-review-harnessB.md` (запись в файл — по требованию) |

Примечание про модели: инструмент агентов в этой сессии принимает тиры
sonnet/opus/haiku/fable; явные имена `deepseek-pro`/`deepseek-flash` недоступны, поэтому
сопоставление: **opus ≈ deepseek-pro** (сильный), **haiku ≈ deepseek-flash** (дешёвый/быстрый).

**Вывод по времени: метод B (скелет→тела) ≈ в 2 раза быстрее** метода A по агентному времени.

## Наблюдения о связке скелет→тела

- **Контракт соблюдён**: список экспортов байт-в-байт идентичен каркасу — агент тел не сломал
  ни одной сигнатуры и следовал комментариям (структурная целостность подтверждена).
- Но **в логике появился баг, которого нет в дизайне** (персист пустого плейсхолдера) — дешёвый
  тир реализовал «по комментарию», не увидев граничный сценарий, который спецификация покрывала
  в D-13/D-17 косвенно. Плюс мелкая небрежность: скелетные формулировки утекли в KDoc продукта.
- Сильный тир на каркасе + слабый на телах **ускорили в 2 раза, но понизили качество**.

## Вывод

1. **Быстрее — метод B** (≈8 мин против ≈17 мин агентного времени).
2. **Качественнее — метод A**: 0 багов кода против 2 (один из них — пользовательский тупик
   беседы), меньше замечаний ревьюера (4 против 8).
3. Рекомендация: двухфазный харнесс оставить (выигрыш по скорости реален), но
   (а) тела методов писать на среднем/сильном тире, а дешёвый оставить только механическим
   задачам; либо (б) сохранить дешёвые тела, но добавить обязательный ранний цикл
   «ревью → фикс» сразу после фазы тел, чтобы ловить граничные баги до сдачи.
